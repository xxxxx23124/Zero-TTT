# 历史与战略记忆

状态：未来研究。

## 假设

纯 Transformer 已编码固定长度棋盘历史，但没有一盘棋内持续更新的显式内部状态。独立快
记忆可能压缩更长历史、对手风格和计划进展，也可能只是昂贵地重复当前棋盘信息。

## 候选语义

- 对局开始时，从共享、可学习模板复制黑白私有状态。
- 仅在真实落子边界更新；MCTS 推演节点不永久写入。
- 本方更新可读取公共轨迹、模型输出和本方旧状态，对手私有状态不可见。
- 状态通过有界残差调节 policy/value，不替换慢模型主干。

## 序列训练边界

- 从 `TrajectoryRecord` 抽取不跨棋局的连续 `[burn-in + train]` 子序列。
- burn-in 只按当前模型重放并恢复快状态，不计算训练 loss；train 段才反向传播。
- 快状态不写入分片，因为其语义依赖模型和更新器版本。
- 同一子序列只选择一个 D4 对称变换，不能逐步独立旋转。
- 早期使用截断反向传播和明确梯度开关，先控制显存。

训练目标仍是后续 policy/value/score；不能只做状态自重建便假设棋力提升。序列分片契约见
[持久数据设计](../../../src/zero_ttt/data/trajectory-storage.md)。

## 首要问题

- 当前棋盘与最近 8 步特征是否已经足够？
- 快状态是真正依赖长历史，还是坍缩为常量偏置？
- 对弈双方状态分歧能否作为诊断，而不泄漏为额外输入？
- 计算与显存收益是否优于增加主干或显式上下文？
