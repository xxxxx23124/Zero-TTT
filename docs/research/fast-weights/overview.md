# 快权重研究总览

状态：未来实现，启动条件是更换显存更充足的 GPU。当前超网络是每次前向产生动态残差，
不等同于跨回合持久的快权重状态。

## 两条路线

- [历史与战略记忆](trajectory-memory.md)：从真实对局历史更新状态，尝试形成一盘棋内持久战略。
- [搜索摘要记忆](search-memory.md)：将一次强搜索压缩到快状态，用于后续局面的策略修正。

两者可以组合：历史记忆提供长期上下文，搜索记忆写入局部计算成果。必须通过消融判断它们
是否提供互补信息，而不是一开始绑定为不可拆的结构。

## 继承的研究原则

- 慢模型负责通用围棋能力，快状态只作为可关闭残差。
- 黑白可以从同一可学习模板复制出各自私有状态，避免信息越权。
- 对手真实落子可作为后续输入，但不允许直接读写对手私有记忆。
- 快状态有明确的棋局、玩家、模型和版本归属，不跨局默认继承。
- 快权重不能被宣传为完整搜索树的等价替代。

## 与搜索兼容

快权重并不排斥 MCTS。一次搜索中冻结
`(base_model_version, fast_state_version, feature_schema, rules)`，搜索结束后至多写入一次；
一旦写入，旧树和缓存失效。详细不变量见
[MCTS 兼容性](../../integrations/mcts-compatibility.md)。

风险、对照和恢复标准见[实验与风险](evaluation.md)。
