# 快权重研究总览

状态：未来实现，启动条件是更换显存更充足的 GPU。当前超网络是每次前向产生动态残差，
不等同于跨回合持久的快权重状态。

## 两条路线

- [历史与战略记忆](trajectory-memory.md)：从真实对局序列更新状态，形成一盘棋内持久战略。
- [搜索摘要记忆](search-memory.md)：将 OpenSpiel MCTS 或教师搜索摘要写入快状态。

两者可以组合，但必须消融验证是否互补。新持久层从第一版保存完整轨迹与搜索摘要，避免
未来重新采集；模型相关快状态本身不落盘。

## 继承的研究原则

- 慢模型负责通用围棋能力，快状态只作为可关闭残差。
- 黑白从同一模板复制各自私有状态，不直接读写对手私有记忆。
- 快状态有明确棋局、玩家、模型和版本归属，不跨局默认继承。
- 快权重不能被宣传为搜索树的等价替代，MCTS 仍是默认提升算子。

## 与搜索兼容

一次搜索中冻结 `(base_model_version, fast_state_version, feature_schema, rules, search_config)`；
搜索结束后至多写入一次。一旦写入，旧树和 evaluator cache 失效。OpenSpiel 当前每着创建新
根，天然符合默认清树策略；仍需隔离外部推理缓存。

数据边界见[序列化训练数据](../../architecture/trajectory-storage.md)，风险与恢复标准见
[实验与风险](evaluation.md)。
