# Zero-TTT 实施计划

> 状态：实现准备阶段
>
> 最近更新：2026-08-17

Zero-TTT 当前目标是在标准 19×19 围棋上完成一套适合个人学习、实践和娱乐的 AlphaZero 风格系统。项目允许先用许可清晰的开源棋谱预训练，再进入神经网络引导的 MCTS 与自博弈训练；不追求严格复现 DeepMind 的训练规模，也不设置必须达到的棋力等级。

稳定选择记录在[设计决策](design_decisions.md)，可随时修改的玩法记录在[实验点子](ideas.md)，实际工作与结果记录在[开发日志](devlog/README.md)。旧快记忆研究方案已经移入[历史归档](archive/fast-memory-2026/README.md)。

## 实施原则

- 优先级依次为：能运行、能理解、能玩、方便试验、最后才是性能。
- 正式目标固定为 19×19；可以使用构造局面和小样本测试组件，但不建立小棋盘产品路线。
- 标准 AlphaZero 风格路径必须独立可用，实验机制通过明确接口接入。
- 正确性验证是必要条件；棋力提升、论文式消融和排行榜成绩不是完成条件。
- 网络规模、搜索预算、批量大小和更新频率保持配置化，以单卡实际运行结果为准。
- 数据来源和许可证与模型 checkpoint 一样是可复现性的一部分。

## 里程碑 1：围棋规则与状态

**目标**

建立可供数据复盘、MCTS、自博弈和 GTP 共用的 19×19 围棋环境。

**第一版语义**

- 19×19 棋盘，动作空间为 361 个交叉点加 `pass`。
- 默认贴目 7.5，可由对局或 GTP 命令覆盖。
- 自博弈使用 Tromp–Taylor 风格面积计分。
- 支持提子、自杀禁手、劫与超级劫、连续两次 `pass` 终局以及异常长对局保护。
- 神经网络输入和值目标统一使用当前行棋方视角。

**交付物与验收**

- 不可变或可安全复制的棋局状态、合法动作、落子、终局与计分接口。
- 状态历史或等价哈希机制，足以执行选定的超级劫规则。
- 覆盖提子、自杀、劫、超级劫、pass、贴目、终局和视角翻转的测试。
- 固定棋局可以逐手重放，并在终局得到预期结果。

## 里程碑 2：开源棋谱与训练样本

**目标**

用统一数据接口接入普通 SGF 和包含搜索信息的富自博弈记录。

**数据接口**

每个训练样本至少包含：局面、合法动作掩码、策略目标、当前方视角的价值目标、数据来源与棋局标识。可选字段可以包含根访问次数、根价值、搜索预算和规则元数据。

- 普通 SGF 使用实际落子的 one-hot 策略目标和最终胜负价值。
- 富自博弈记录如果提供有效的 MCTS 访问次数，则归一化为策略目标，优先于实际落子的 one-hot 目标。
- 数据来源不限定为人类或程序；第一版只接收 19×19、结果明确、规则可解释并能完整合法复盘的对局。
- 训练/验证划分以整盘棋为单位，避免同一棋局的相邻局面泄漏。
- 训练时支持围棋八种旋转与镜像对称变换。

**交付物与验收**

- SGF 适配器、富自博弈数据适配器和统一样本表示。
- 数据清单记录下载位置、许可证、校验值、格式版本、过滤条件和样本统计。
- 非法、截断、尺寸不符或结果未知的记录被明确拒绝或隔离，并报告原因。
- 使用小型固定数据集可以重复生成完全相同的训练样本。

KataGo g104 等采用 CC0 的自博弈档案可作为第一批候选数据和适配器参考，但在实际下载前仍需记录具体版本、文件和校验值。

## 里程碑 3：策略—价值网络预训练

**目标**

建立能够为 MCTS 提供有效先验和叶节点价值的基础网络。

**交付物**

- 共享残差骨干、362 维策略头和标量价值头。
- 合法动作屏蔽、策略交叉熵、价值损失、优化器和 checkpoint。
- 配置化的网络宽度、残差块数量、精度、批量大小和数据加载参数。
- 训练、验证、指标记录和断点恢复入口。

**验收门槛**

- 极小数据集能够被网络过拟合，策略和值损失明显下降。
- 非法动作不会进入用于选择动作的归一化策略。
- 棋盘对称变换后的标签和值视角保持正确。
- 保存并重新加载 checkpoint 后，相同输入产生容差内一致的结果。

## 里程碑 4：PUCT MCTS

**目标**

实现由当前策略—价值网络引导、可测试且适合后续批量优化的搜索。

**交付物**

- 选择、扩展、神经网络评价、价值备份和根访问分布。
- 根节点探索噪声、温度选子、搜索统计和合法动作处理。
- 批量神经网络评价边界；第一版可以先顺序调度，再优化并发吞吐。
- 搜索配置与随机数状态的完整记录。

**验收门槛**

- 固定模型、局面、配置和随机种子时搜索结果可重复。
- 换手时价值符号和备份方向正确。
- 所有访问动作合法，零访问或终局等边界情况有明确行为。
- 增加搜索次数时，固定测试局面的根分布和值总体趋于稳定。

## 里程碑 5：自博弈与训练闭环

**目标**

完成数据生成、训练、候选模型评估、冠军模型更新和恢复流程。

**交付物**

- 自博弈工作器、经验回放、训练器和独立评估对局。
- 当前训练模型、候选模型和冠军模型的明确生命周期。
- 完整 checkpoint：模型、优化器、训练步数、随机数状态、数据游标和配置标识。
- 训练与自博弈指标，包括损失、对局长度、结果分布、搜索吞吐和候选对局结果。

**验收门槛**

- 一个小规模端到端运行能够从数据生成持续到候选模型评估。
- 进程中断后可以恢复，不会静默重置训练状态或混用数据版本。
- 生成的每盘棋都能重新合法复盘，训练样本与搜索统计对应。
- 不要求候选模型达到指定棋力；如果模型退化，流程必须能够显示而不是掩盖它。

## 里程碑 6：GTP 可玩引擎

**目标**

让训练得到的模型能够通过常见棋盘软件与人对弈。

**第一版命令**

支持 GTP v2 的基础协议查询，以及 `boardsize 19`、`clear_board`、`komi`、`play`、`genmove`、`undo`、`final_score` 和 `quit`。其他棋盘尺寸返回明确的“不支持”错误。

**验收门槛**

- 协议输出不会被日志污染，错误命令得到合法 GTP 错误响应。
- 可以通过 Sabaki、q5Go 或等价控制器启动、落子、悔棋并完成整盘对弈。
- GTP、离线自博弈和规则测试使用同一个围棋环境，不复制规则逻辑。

## 里程碑 7：可插拔点子实验

**目标**

在基线闭环保持可运行的前提下，为“三速大脑”和后续想法提供最小实验边界。

**第一项实验**

- `anchor`：一个实验周期内冻结的参考或冠军模型。
- `slow`：以 EMA 或其他缓慢规则跟随训练状态的模型。
- `fast`：每个周期从 `slow` 初始化并接受正常梯度更新的模型。
- 如果配置规定的评估确认 `fast` 持续无法战胜 `anchor`，允许用 `anchor` 重置 `slow`。

实验需要能够保存、加载并区分三份权重，记录初始化、更新和重置事件。EMA 系数、周期长度、失败阈值和重置方式属于单次实验配置，不在主线文档中固定。实验无需证明比基线更强，但必须能够被完全关闭。

## 当前待办顺序

1. 确定根包结构、依赖与配置系统。
2. 实现里程碑 1 的规则状态和测试。
3. 调查并登记第一批许可清晰的 19×19 开源棋谱。
4. 用最小数据适配器和小网络完成预训练冒烟测试。
5. 再进入 MCTS 和自博弈闭环；实验点子不得提前阻塞这些步骤。
