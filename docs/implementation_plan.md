# Zero-TTT 实施计划

> 状态：尚未正式开发
> 最近更新：2026-08-12

本文件负责会随工程进展变化的计划。核心算法语义以 [研究设计](research_design.pdf) 为准，重要选择形成后记录到 [设计决策](design_decisions.md)，实际工作写入 [开发日志](devlog/README.md)。

## 实施原则

- 先证明每个基础组件正确，再引入快记忆和元梯度。
- 每个里程碑必须留下可重复的最小验证，不能只以“程序能运行”作为完成条件。
- 模型规模、搜索预算和硬件优化从小型实验逐步确定，不在代码开工前绑定旧方案中的数值。
- 快记忆收益必须与无记忆、每手重置和搜索树复用对照，避免把额外参数或缓存收益误认为搜索压缩。

## 里程碑 1：传统策略—价值基线

**目标**

建立不含快记忆的可靠围棋策略—价值模型和训练闭环。

**前置条件**

- 明确第一版支持的棋盘、规则、输入特征和动作编码。
- 选定许可清晰且目标语义可验证的自博弈数据。

**交付物**

- 可测试的规则环境与状态编码。
- 标准策略—价值网络、训练入口和基础 checkpoint。
- 数据检查、合法动作屏蔽、价值视角和对称变换测试。

**验收门槛**

- 固定棋谱上的规则、动作和终局视角全部通过测试。
- 策略输出对非法动作严格屏蔽，价值视角在换手后保持一致。
- 基线模型在保留数据上明显优于随机预测，并能稳定提供 MCTS 先验和叶值。

## 里程碑 2：冻结权重的 MCTS

**目标**

建立参数在单次搜索内严格冻结的顺序 MCTS，并形成可靠的无快记忆基线。

**前置条件**

- 里程碑 1 的规则与基础网络通过验收。

**交付物**

- MCTS 选择、扩展、备份、根策略和动作选择流程。
- 搜索摘要的概念实现：节点路径、相对角色、访问策略、搜索价值和置信度。
- “每手丢弃树”和“合法时复用子树”两种基线模式。

**验收门槛**

- 同一模型状态和随机种子能够重复搜索结果。
- 搜索期间模型版本保持不变，价值换边备份正确。
- 增加搜索预算时，固定测试局面的策略和价值总体趋于稳定。

## 里程碑 3：独立快记忆分支

**目标**

在不修改基础路径语义的前提下加入大容量非线性快记忆，并实现搜索后单次写入。

**前置条件**

- 冻结 MCTS 和搜索摘要接口稳定。
- 通过小型基准确定第一版记忆网络家族和安全门控方式。

**交付物**

- 独立记忆网络、查询投影、策略/价值残差读出和输出门控。
- 写入集与保留集划分，以及策略—价值写入损失。
- 一次搜索后的一步快权重更新；当前动作仍取自更新前的搜索。

**验收门槛**

- 关闭记忆门时输出与传统基线一致。
- 搜索期间快权重不变，搜索结束后只有当前方快权重改变。
- 写入损失下降且更新幅度有限，不产生非有限策略或价值。

## 里程碑 4：可学习模板与局部元训练

**目标**

让共同模板和记忆控制参数学习“怎样通过一次搜索梯度形成可泛化记忆”。

**前置条件**

- 快记忆的数值更新稳定。
- 搜索摘要能够可靠重放写入节点、保留节点和下一次本方根局面。

**交付物**

- 模板重锚定、单步可微更新和精确二阶元梯度。
- 同树保留损失与下一次本方根损失。
- 数值快状态跨手保留、高阶计算图按手释放的训练回放。

**验收门槛**

- 小型模型的有限差分与自动微分结果在容差内一致。
- 模板、查询/读出投影、门控和写入尺度获得有限且非零的外层梯度。
- 学习后的模板在保留节点上优于固定随机模板和每手零初始化。

## 里程碑 5：黑白私有记忆闭环

**目标**

完成共享模板、双私有运行时状态和整盘搜索—写入自博弈。

**前置条件**

- 单方快记忆回放和元训练通过验收。

**交付物**

- 每盘从共同模板复制黑白两份独立状态。
- 搜索拥有者在整棵模拟树中始终使用自己的记忆和相对角色。
- 双方对称的片段采样、损失归一和终局状态销毁。

**验收门槛**

- 修改一方的搜索摘要或快记忆不会改变另一方的运行时状态。
- 对手真实落子不会触发自己的即时写入；下一次本方搜索能自然读取新棋盘。
- 交换颜色和相对视角后，共同模板的学习与推理语义保持一致。

## 里程碑 6：实验评估

**目标**

判断快记忆是否真正摊销了过去 MCTS 的计算，而不只是拟合当前搜索节点。

**前置条件**

- 完整双私有记忆闭环可重复运行。

**交付物**

- 无记忆、树复用、每手重置、整盘私有记忆和高预算重置对照。
- 同树保留、跨回合根预测、搜索预算—质量曲线和黑白记忆分歧报告。
- 记忆重置和交换的离线因果实验。

**验收门槛**

- 明确报告每项核心假设得到支持、未得到支持或证据不足。
- 主要结论必须在未参与写入的局面上成立。
- 任何性能提升都能与额外网络计算、树复用和基础模型变化区分。

## 实施前待定项

下列项目有意不在研究主文档中固定。进入相关里程碑前，应先做最小实验，再把决定写入 `design_decisions.md`：

- 第一版围棋规则、棋盘范围、输入特征和动作编码。
- 自博弈数据来源、许可、解析方式和辅助目标。
- 基础模型与快记忆的规模、结构和初始化方式。
- 搜索预算、节点筛选、写入集/保留集划分和损失权重。
- 数值精度、设备目标、批量策略、显存控制和性能优化。
- 轨迹格式、checkpoint、恢复、容器和依赖版本。

## 计划维护

- 里程碑可以拆成冲刺，但冲刺日期和人员安排只写在本文件或外部任务系统中。
- 某个待定项形成稳定选择后，新增一条设计决策，并在此处引用其编号。
- 每次完成实际工作后新增开发日志；失败实验同样记录，不从历史中删除。
