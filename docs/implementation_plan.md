# Zero-TTT 实施计划

> 状态：里程碑 1、4、5 首版已实现，生产 GPU 验收待完成
>
> 最近更新：2026-08-18

Zero-TTT 当前目标是在标准 19×19 围棋上完成一套适合个人学习、实践和娱乐的 AlphaZero 风格系统。项目允许先用许可清晰的开源棋谱预训练，再进入神经网络引导的 MCTS 与自博弈训练；不追求严格复现 DeepMind 的训练规模，也不设置必须达到的棋力等级。

稳定选择记录在[设计决策](design_decisions.md)，模型、训练和搜索的当前实现规格集中在[模型与搜索设计](model_search_design.md)，可随时修改的玩法记录在[实验点子](ideas.md)，实际工作与结果记录在[开发日志](devlog/README.md)。旧快记忆研究方案已经移入[历史归档](archive/fast-memory-2026/README.md)。

## 实施原则

- 正确性、可恢复性和可解释性优先；在语义边界清楚后，主动优化单卡吞吐和样本效率。
- 正式目标固定为 19×19；可以使用构造局面和小样本测试组件，但不建立小棋盘产品路线。
- 标准 AlphaZero 风格路径必须在关闭低秩超网络等实验机制时独立可用。
- 正确性验证是必要条件；棋力提升、论文式消融和排行榜成绩不是完成条件。
- 当前硬件档的网络规模、搜索预算、批量大小和更新频率由模型与搜索规格定义，并由版本化 TOML 配置实例化；不接受零散命令行覆盖。
- 不设置候选模型对冠军模型的竞技评估、晋升或自动回退；低成本验证只负责发现问题。
- 数据来源和许可证与模型 checkpoint 一样是可复现性的一部分。

## 里程碑 1：围棋规则与状态

**状态：** 首版已实现并由规则、特征和 D4 单元测试覆盖。

**目标**

建立可供数据复盘、MCTS、自博弈和 GTP 共用的 19×19 围棋环境。

**第一版语义**

- 19×19 棋盘，动作空间为 361 个交叉点加 `pass`。
- 默认贴目 7.5，可由对局或 GTP 命令覆盖。
- 自博弈使用 Tromp–Taylor 风格面积计分。
- 支持提子、自杀禁手、劫与超级劫、连续两次 `pass` 终局以及异常长对局保护。
- 神经网络输入和值目标统一使用当前行棋方视角。

**交付物与验收**

- 不可变或可安全复制的棋局状态、合法动作、落子、终局与计分接口。
- 状态历史或等价哈希机制，足以执行选定的超级劫规则。
- 覆盖提子、自杀、劫、超级劫、pass、贴目、终局和视角翻转的测试。
- 固定棋局可以逐手重放，并在终局得到预期结果。

## 里程碑 2：开源棋谱与训练样本

**状态：** 未实现。当前只预留 `GameSource → GameRecord → ReplayStore` 边界；SGF、下载和外部数据适配不在本轮范围。

**目标**

用统一数据接口接入普通 SGF 和包含搜索信息的富自博弈记录。

**数据接口**

每个训练样本至少包含：局面、合法动作掩码、策略目标、当前方视角的价值目标、数据来源与棋局标识。可选字段可以包含根访问次数、根价值、实际搜索预算、所有权目标、目差目标、辅助标签掩码和规则元数据。

- 普通 SGF 使用实际落子的 one-hot 策略目标和最终胜负价值。
- 富自博弈记录如果提供有效的 MCTS 访问次数，则归一化为策略目标，优先于实际落子的 one-hot 目标。
- 数据来源不限定为人类或程序；第一版只接收 19×19、结果明确、规则可解释并能完整合法复盘的对局。
- 训练/验证划分以整盘棋为单位，避免同一棋局的相邻局面泄漏。
- 训练时支持围棋八种旋转与镜像对称变换。
- 自博弈样本记录实际搜索预算；辅助标签缺失时使用显式掩码，不伪造零标签。

**交付物与验收**

- SGF 适配器、富自博弈数据适配器和统一样本表示。
- 数据清单记录下载位置、许可证、校验值、格式版本、过滤条件和样本统计。
- 非法、截断、尺寸不符或结果未知的记录被明确拒绝或隔离，并报告原因。
- 使用小型固定数据集可以重复生成完全相同的训练样本。

KataGo g104 等采用 CC0 的自博弈档案可作为第一批候选数据和适配器参考，但在实际下载前仍需记录具体版本、文件和校验值。

## 里程碑 3：策略—价值网络预训练

**状态：** Transformer、损失、优化器和 checkpoint 基础已随核心闭环实现；开源数据适配、监督预训练命令、小数据过拟合与生产 GPU 验收尚未完成。

**目标**

建立能够为 MCTS 提供有效先验和叶节点价值、适配 16 GB 单卡的棋盘 Transformer。

**交付物**

- 24 层、`d_model=1024`、16 头、SwiGLU `d_ff=2816` 的 Transformer Encoder，使用 361 个棋盘 token、一个全局 token 和 2D RoPE。
- Pre-RMSNorm、QK-Norm、深度缩放残差初始化、零 dropout、362 维策略头、标量价值头、所有权头和目差头。
- PyTorch SDPA、BF16 autocast、fused AdamW、隔层非重入 activation checkpoint，以及分离的 eager/compile 训练与推理路径。
- 物理 batch 16、默认梯度积累 16 步、全局梯度裁剪 `1.0`；辅助损失使用可用性掩码。
- 只从版本化 TOML 加载的严格配置，以及包含配置 schema、哈希和完整训练状态的 checkpoint。
- 训练、低成本验证、健康指标记录和断点恢复入口；验证结果不参与模型晋升或回退。

**验收门槛**

- 极小数据集能够被网络过拟合，策略和值损失明显下降。
- 非法动作不会进入用于选择动作的归一化策略。
- 2D RoPE、全局 token、棋盘对称变换后的策略/所有权标签和值视角保持正确。
- 保存并重新加载 checkpoint 后，相同输入产生容差内一致的结果。
- Eager/compile 与 checkpoint 开关的输出、损失和梯度在规定容差内一致。
- 最终训练图完成编译后，batch 16 的峰值保留显存不超过 14.5 GiB；超限时增加 checkpoint 覆盖率，不缩小既定模型。

## 里程碑 4：PUCT MCTS

**状态：** Python 参考后端、集中批量推理、版本化缓存、树复用和并发虚拟损失首版已实现；C++ 后端不在本轮范围。

**目标**

实现由已发布 `slow` 模型引导、支持 16 线程共享调度和 batch 16 推理的搜索。

**交付物**

- 选择、扩展、神经网络评价、价值备份和根访问分布。
- 一个集中叶节点队列、一个模型实例和共享的 16 线程搜索池；请求按模型版本分组、去重并组成最大 batch 16。
- 真实落子后的树复用，以及包含完整规则/特征历史身份和模型版本隔离的 LRU 神经评价缓存；不同树节点不共享访问统计，首版不采用 DAG 备份。
- 每次下降 1 个且可在成功、取消、异常路径完整撤销的虚拟损失。
- 自博弈根使用权重 `0.25`、总浓度 `10.83` 的 Dirichlet 噪声；未访问节点使用规定的 FPU 初值。
- 256/512/768/1024 四档动态搜索预算、温度选子、搜索统计和合法动作处理。
- 搜索配置、实际使用预算、各检查点统计和随机数状态的完整记录。

**验收门槛**

- 单线程下固定模型、局面、配置和随机种子时搜索结果可重复；16 线程只要求规则正确、无死锁和配置可复现，不承诺逐次访问数相同。
- 换手时价值符号和备份方向正确。
- 所有访问动作合法，零访问或终局等边界情况有明确行为。
- 增加搜索次数时，固定测试局面的根分布和值总体趋于稳定。
- 缓存不跨规则、超级劫历史或模型版本复用，哈希命中后执行精确状态核验。
- 动态预算的四个停止边界、FPU 和根噪声启用范围均有确定性测试。
- 16 线程压力测试结束后不存在残留虚拟损失、悬挂请求或跨版本合批。

## 里程碑 5：自博弈与训练闭环

**状态：** 单 GPU 分阶段参考闭环已实现并通过 tiny 端到端恢复测试；长期运行监控、固定局面报警和生产吞吐调优仍待补充。

**目标**

完成数据生成、滑动窗口回放、`fast` 训练、`slow` EMA 发布和恢复流程，不设置竞技门控。

**交付物**

- 自博弈工作器、按整盘 FIFO 淘汰且默认容纳 2,000,000 个局面的经验回放，以及 D4 在线增强。
- `fast` 每步梯度更新；`slow` 以 `1,048,576` 个样本为 EMA 半衰期，每 16 个优化器步骤做一次等效更新，每 256 步发布不可变快照。
- 自博弈和 GTP 只使用已发布 `slow`；一盘棋和一次 MCTS 内模型版本固定，`fast` 不直接产数。
- 完整 checkpoint：`fast`、FP32 `slow`、优化器、调度器、训练步数、样本计数、EMA 状态、随机数状态、数据游标、回放元数据和配置哈希。
- 训练与自博弈指标，包括主/辅助损失、梯度范数、EMA 距离、对局长度、结果分布、缓存命中率、批量填充率和搜索吞吐。
- 小型固定验证集和固定局面回归；结果只记录和报警，不阻塞训练、不触发自动回退。

**验收门槛**

- 一个小规模端到端运行能够从数据生成持续到 `slow` 快照发布和新数据消费。
- 进程中断后可以恢复，不会静默重置训练状态或混用数据版本。
- 生成的每盘棋都能重新合法复盘，训练样本与搜索统计对应。
- 不要求模型达到指定棋力；如果指标退化，流程必须显示而不是掩盖它，但不得据此自动重置 `slow`。
- 任一输出、损失或梯度出现 NaN/Inf 时保存故障 checkpoint 并停止。

## 里程碑 6：GTP 可玩引擎

**状态：** 未实现。

**目标**

让训练得到的模型能够通过常见棋盘软件与人对弈。

**第一版命令**

支持 GTP v2 的基础协议查询，以及 `boardsize 19`、`clear_board`、`komi`、`play`、`genmove`、`undo`、`final_score` 和 `quit`。其他棋盘尺寸返回明确的“不支持”错误。

**验收门槛**

- 协议输出不会被日志污染，错误命令得到合法 GTP 错误响应。
- 可以通过 Sabaki、q5Go 或等价控制器启动、落子、悔棋并完成整盘对弈。
- GTP、离线自博弈和规则测试使用同一个围棋环境，不复制规则逻辑。

## 里程碑 7：可插拔点子实验

**状态：** 完整低秩超网络代码、冻结/ramp、优化器分组和稳定性测试已实现，配置默认关闭；尚未进行棋力或训练稳定性实验。

**目标**

在基线闭环保持可运行的前提下，为完整低秩超网络和后续想法提供最小实验边界。

**第一项实验**

- 默认关闭，只接入最后 4 个 Transformer 层的 FFN 下投影。
- 每个局面由全局 token 生成一组完整的 `A(x) ∈ R^(1024×8)` 和 `B(x) ∈ R^(8×2816)`，同一局面的棋盘 token 共享。
- 动态残差为 `gamma * A(x)(B(x)h) / sqrt(8)`；超网络隐藏宽度为 128，启用后总参数约 3.25 亿。
- A/B 输出有界，B 输出头零初始化，上下文梯度缩放 `0.1`；超网络学习率倍率与独立梯度裁剪均为 `0.1`。
- 先冻结 2,000 个优化器步骤，再用 10,000 步把动态分支从 0 线性放大到完整强度。

实验配置、冻结/解冻进度、动态分支尺度和超网络优化器分组必须进入 checkpoint。实验无需证明比基线更强，但必须能够完全关闭；关闭后 checkpoint 不得要求存在超网络参数。非有限值立即停训并保留故障现场，不以 `slow` 或旧快照自动回退。

## 当前待办顺序

1. 在目标 RTX 4090 Laptop Linux 容器运行正式模型的 eager/compile、超网络开关与 batch 16 显存冒烟，确认峰值不超过 14.5 GiB。
2. 增加极小固定数据集过拟合、固定局面非阻塞报警和更完整的长期吞吐/缓存指标。
3. 调查并登记第一批许可清晰的 19×19 开源棋谱，通过统一 `GameSource` 适配写入回放。
4. 实现监督预训练模式；不把外部数据解析逻辑耦合进 Trainer。
5. 实现 GTP；Python 搜索后端稳定后再评估 C++ 替换。
