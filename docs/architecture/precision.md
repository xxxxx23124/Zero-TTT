# 严格 FP32 精度策略

状态：D-040 已接受并实现。Zero-TTT 在可预见的长期内固定使用严格 FP32，不把精度暴露为
实验配置，也不按设备自动选择较低精度。

## 为什么默认 FP32

Zero-TTT 是强化学习项目，训练信号来自策略、价值和自博弈分布的持续变化。部分有效梯度可能
很小；在 16 位计算中，它们可能因下溢直接变成 0，也可能因尾数精度不足而被舍入，无法相对
当前参数形成可表示的更新。loss scaling 可以缓解部分 FP16 下溢，但不能恢复已经丢失的尾数
信息，也不能消除不同算子和设备带来的量化差异。

超网络又增加了一层敏感性：生成参数或调制量不仅参与主网络计算，更新信号还要沿这条依赖链
回传到超网络。这里不预设 16 位一定导致训练失败，但目前也没有足够证据证明这种精度损失对
长期强化学习和超网络调整无害。因此项目选择用 FP32 排除这类数值变量，使训练、恢复、发布和
推理共享一种容易理解和排查的语义。

这是一项优先方便与求稳的工程取舍，而不是吞吐优化。FP32 本身不保证收敛，但能减少精度转换、
loss scaling、训练/推理差异和设备相关行为带来的复杂度；项目接受由此产生的速度损失。

## 覆盖范围

以下神经网络状态和计算必须使用 `torch.float32`：

- 模型输入、参数、buffer、激活、损失、梯度和 AdamW 浮点状态；
- CPU slow/EMA、完整 checkpoint 与不可变 publication；
- publication evaluator 的权重、前向输出及推理公共契约。

棋盘索引、合法着 mask、随机状态和计数器继续使用领域所需的整数或布尔类型。MCTS、catalog
和采样器的主机侧统计可以保留算法需要的 NumPy 精度；它们不属于模型精度策略。bool mask
参与损失时转成 FP32、张量在 CPU/GPU 之间搬运都不是精度降级。

## 执行约束

- `torch.set_float32_matmul_precision("highest")`；
- CUDA matmul 与 cuDNN 的 TF32 均关闭；
- 活动的一方代码不得使用 BF16/FP16 dtype 或 autocast；
- 模型及推理契约拒绝非 FP32 浮点输入，不静默转换；
- publication 写入和加载都校验 FP32 权重。

未来若要研究其他精度，必须重新形成架构决策并提升相关 schema；不得在现有配置中加入隐式
fallback 或依据 GPU 型号改变计算语义。

## 产物与运行

实验配置和模型产物当前都是 schema v7。checkpoint 与 publication 写入
`tensor_precision = "float32"`；v6 产物不迁移、不加载，也不会被程序删除。正式配置使用新的
`rtx4090l-625m-fp32` run 身份，旧数据 catalog 和不可变 snapshot 仍可复用。

训练和自博弈按阶段创建 Learner 或 evaluator，不要求两个 GPU 模型同时常驻。RTX 4090 Laptop
的 batch-16 实测中，默认模型 eager/compiled 训练峰值分别为 13.127/13.307 GiB reserved，
FP32 推理分别为 3.979/4.295 GiB；baseline eager 训练/推理分别为 11.766/3.053 GiB。
速度只记录，不作为回退精度的理由。

旧开发日志和 legacy 决策中的 BF16 数字是当时实验事实，不代表当前受支持行为。
