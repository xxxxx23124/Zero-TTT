# 架构决策

2026-08-20 之前的完整决策保留在 Git 历史和开发日志中。被取代不表示相关研究没有价值。

## D-027：只维护 Docker

- **状态：** 已接受
- **决定：** 测试、训练、KataGo 构建和运维只以 Docker/Compose 为支持环境。
- **影响：** 宿主机导入失败不算项目缺陷；README 不提供非 Docker 安装步骤。

## D-028：删除内部 MCTS，采用官方 KataGo

- **状态：** 被 D-036 部分取代
- **保留：** 不恢复自维护 Python PUCT；KataGo v1.17.2 仍提供强教师和独立 GTP。
- **取代：** 学生搜索改用 OpenSpiel Python MCTS，而不是无搜索或 KataGo 加载学生网络。

## D-029：训练只依赖批量数据契约

- **状态：** 已接受
- **决定：** Trainer 只消费 `BatchSource`/`TrainBatch`，不依赖 replay、SGF 或教师协议。
- **影响：** 每种流程适配数据和视角，但复用同一优化、EMA 和 checkpoint。

## D-030：规则与外部资产

- **状态：** 已接受
- **决定：** 规则固定为 19×19 Tromp–Taylor；外部权重单独记录许可并由用户只读挂载。
- **影响：** 本地 `GameState` 是棋规真源，仓库不自动下载或提交模型权重。

## D-031：快权重延期但保持搜索兼容

- **状态：** 已接受
- **决定：** 快权重等待设备升级。搜索内冻结快状态，写入后作废旧树和缓存。
- **影响：** 新数据从第一版保留完整时序，快状态本身不写入数据。

## D-032：本地学生自博弈与可选 MCTS

- **状态：** 被 D-036、D-037 取代
- **原决定：** 先实现纯策略 batch 1，自维护的最小 MCTS 仅为未来选项。
- **取代原因：** raw policy 自博弈没有明确提升算子；AlphaZero 路线改为默认 MCTS 自博弈。

## D-033：Learner 与数据采集分离

- **状态：** 已接受
- **决定：** 目标 Learner 只拥有监督优化、EMA、compile、梯度与状态保存；采集器先落盘。
- **影响：** KataGo adapter、游戏、搜索和课程调度不得进入 Learner 或 `model`。

## D-034：训练与采集同进程分阶段

- **状态：** 已接受
- **决定：** 训练模型和只读 BF16 evaluator 可同时驻留，但默认顺序使用 GPU。
- **影响：** 当前保留 14.5 GiB 双模型验收线，不增加复杂模型换入换出。

## D-035：Human-SL 分级教师

- **状态：** 已接受，由 D-037 补充
- **决定：** 教学和对战绑定完整 profile/搜索身份；400 局、55% 点胜率与 Wilson 下界判定升级。
- **影响：** 晋级只切换教师课程，不是 publication 门控；学生不再被要求关闭 MCTS。

## D-036：OpenSpiel 搜索、本地棋规

- **状态：** 已接受
- **决定：** 固定 OpenSpiel v2.0.1 指定提交，只用 Python `MCTSBot` 和自定义 Evaluator；
  本地 `GameState` 经薄 `pyspiel.Game/State` 适配后参与搜索。
- **影响：** 不采用内置 Go、模型、Learner 或 AlphaZero runner；每着默认新树，扩大采集前聚批。

## D-037：MCTS 默认的统一训练生命周期

- **状态：** 已接受
- **决定：** 监督冷启动后，以 64 至 100 simulations 的 MCTS 自博弈进入 AlphaZero；再用
  70% 高熵与 30% 分阶段随机局面接入分级教师。
- **影响：** 采样比例从 80/0/20，经 70/10/20，验证后到 60/25/15；raw policy 不作改进标签。

## D-038：序列优先的持久数据

- **状态：** 已接受
- **决定：** 一盘一逻辑 trajectory，多盘进入约 128 MiB immutable NPZ shard；annotation
  独立追加，SQLite 只做索引和控制。
- **影响：** `strength` 非必填；agent 身份可验证，评级用可选 `RatingSnapshot`；按完整棋局淘汰。
