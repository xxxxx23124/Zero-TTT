# 统一训练生命周期

状态：已接受的规范性路线，尚未实现。每轮先冻结整盘采集使用的 publication，完成并封存
数据后再训练、更新 EMA、发布下一版；网络 raw policy 不是自身的改进标签。

## 阶段

1. **监督冷启动：** 用许可清晰的历史棋谱、直观教师标签和规则任务建立棋盘空间感，不追求
   复制最强搜索或声明特定段位。
2. **AlphaZero：** 本地棋规通过 OpenSpiel Python MCTS 生成自博弈；根访问分布训练 policy，
   终局结果训练 value，并保留冷启动 rehearsal。
3. **主动教师辅导：** 从学生实际到达的局面中选择最困惑的一部分，由远程 KataGo 高预算
   标注并作为 sidecar annotation 加入训练。
4. **教师升级：** 学生稳定超过当前教师后提升 profile/visits；较弱教师不再作为主要 policy
   标签来源，但旧数据可受控 rehearsal。
5. **长期留档：** 保存分级 publication、固定评测与关键数据，用于回归、人机对战和未来
   快权重对照。

## 初始采样配方

比例是第一版可标定默认值，不是永恒常数：

| 阶段 | MCTS 自博弈 | 教师 annotation | 冷启动/旧阶段 rehearsal |
| --- | ---: | ---: | ---: |
| 冷启动 | 0% | 0% | 100% |
| 无教师 AlphaZero | 80% | 0% | 20% |
| 教师初接入 | 70% | 10% | 20% |
| 验证无回退后 | 60% | 25% | 15% |

每次运行把实际比例、来源 manifest 和样本数写入训练记录。只有固定评测显示教师收益且冷启动
能力无明显回退，才从初接入逐步过渡到后一配方。

## MCTS 默认值

- 初始每步 64 simulations，先验证闭环，再以吞吐和棋力标定到最多约 100。
- 自博弈根节点加入 Dirichlet 噪声；实际温度、噪声参数和随机种子进入搜索身份。
- 合法子节点访问数归一化为 policy 标签；value 仍来自整盘终局结果。
- 上游 Python `MCTSBot` 每次调用创建新根，因此默认每着清树，不承诺树复用。
- 扩大数据量前必须支持多棋局并发与统一 GPU evaluator 聚批。

## 教师查询和升级

初期查询预算中，70% 分配给归一化学生策略熵最高的局面，30% 按开局/中盘/终局分层随机
抽取；两部分都去重并设置每局上限，避免一盘异常棋占满队列。熵只是疑惑度启发式，必须与
随机样本对照。

教师接入和升级都先用冻结配置对战验证。候选教师应可靠胜过当前学生；学生反过来满足
[分级教师](curriculum-teachers.md)的 400 局/Wilson 门槛后，才提升教师 profile 或预算。
Human-SL 阶段只表示课程身份，不等同精确人类段位。

序列存储见[数据契约](../architecture/trajectory-storage.md)，搜索边界见
[OpenSpiel MCTS](../integrations/mcts-compatibility.md)。
