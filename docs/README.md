| 文档 | 职责 | 稳定程度 |
| --- | --- | --- |
| [研究设计（PDF）](research_design.pdf) / [LaTeX 源码](research_design.tex) | 研究问题、数学定义、信息边界、训练逻辑和可证伪假设 | 高；只在核心方法变化时修改 |
| [实施计划](implementation_plan.md) | 里程碑、交付物、验收门槛和实施前待定项 | 中；随着开发推进持续调整 |
| [设计决策](design_decisions.md) | 已接受的重要选择、理由及其影响 | 中高；新增记录，避免悄悄改写历史 |
| [开发日志](devlog/README.md) | 按日期记录实际工作、实验结果、问题和下一步 | 低；开发期间频繁追加 |

## 维护规则

- `research_design` 不记录模型尺寸、搜索次数、硬件预算、代码路径、依赖版本或冲刺日期。
- 工程参数和阶段安排写入 `implementation_plan.md`；形成长期约束的选择同步记入 `design_decisions.md`。
- 实际完成的工作和实验结果写入 `devlog/`，不能用计划代替日志，也不能把日志中的临时观察直接写成研究结论。
- 研究主文档每次修改后都应重新生成并检查 `research_design.pdf`。
- 文档之间发生冲突时，数学语义以研究设计为准，当前工程状态以实施计划和最新开发日志为准。
