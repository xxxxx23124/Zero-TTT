# Zero-TTT 实验点子

这里是一块允许乱想、乱试、推翻和重写的区域。条目只表示“这个想法值得玩一下”，不表示它正确、有效、已经实现或必须进入主线。

## 使用规则

- 点子可以不做论文式消融，也不需要证明一定提升棋力。
- 每个实验必须能够被关闭，关闭后标准 AlphaZero 风格训练路径仍可运行。
- 真正运行时，把确切配置、checkpoint、结果和问题写入[开发日志](devlog/README.md)。
- 点子经过反复使用并形成长期约束后，才转写为[设计决策](design_decisions.md)。
- 失败、无聊或成本太高的点子可以标记为停止，不必删除历史。

## I-001：冻结—慢速—快速三个大脑

- **状态：** 已转为设计决策
- **动机：** 原点子尝试用冻结锚点、慢速 EMA 和快速训练权重兼顾稳定与响应速度。

### 结论

三权重方案没有进入实现。项目取消了候选模型与冠军模型的竞技门控，也不再维护 `anchor`：

- `fast` 接受训练梯度；
- `slow` 从 `fast` 做稀疏等效 EMA；
- 自博弈、GTP 和发布使用不可变的 `slow` 快照；
- 指标退化只记录，非有限值停训，二者都不会触发自动权重回退。

这一简化已经转为 [D-020](design_decisions.md#d-020取消竞技评估与模型晋升门控) 和 [D-021](design_decisions.md#d-021训练与产数采用-fastslow-双权重)，具体 EMA 语义见[模型与搜索设计](model_search_design.md#5-fast-与-slow)。本条保留用于说明想法如何被取代，不再作为待实现实验。

## I-002：逐局面完整低秩超网络

- **状态：** 工程分支已实现、待实验，默认关闭
- **动机：** 让 Transformer 根据整个棋局状态生成一个低秩线性残差，希望增强对高频、条件化棋形规律的拟合能力，同时把生成矩阵限制在可控规模内。

### 初始玩法

只在最后 4 个 Transformer 层的 FFN 下投影加入动态分支。对于 SwiGLU 隐状态 `h` 和全局棋局 token `c`：

```text
y = W_d h + gamma * A(c) (B(c) h) / sqrt(8)
```

每个局面生成一组完整的 `A(c) ∈ R^(1024×8)` 与 `B(c) ∈ R^(8×2816)`，该局面的 361 个棋盘 token 共享；不为每个 token 单独生成矩阵。超网络先对 `c` 做 RMSNorm，再经过隐藏宽度 128 的 SiLU MLP 和两个独立输出头。rank 固定为 8，启用后总参数约 3.25 亿。

### 稳定措施

- A/B 原始输出经 `tanh` 有界化并按输入维度缩放；B 输出头零初始化，使动态残差从零开始。
- 回到 Transformer 主干上下文的梯度缩放为 `0.1`。
- 超网络使用主干学习率的 `0.1` 倍，独立梯度范数上限为 `0.1`。
- 启用后先冻结 2,000 个优化器步骤，再用 10,000 步把 `gamma` 从 0 线性升到 1。
- 输出、损失或梯度出现 NaN/Inf 时保存故障 checkpoint 并停止，不自动回退到 `slow` 或旧模型。

### 工程边界

- 关闭实验时不创建超网络参数、优化器分组或动态矩阵，标准 Transformer 的输出接口保持不变。
- 实验开关、rank、作用层、冻结/放大进度和优化器分组必须进入配置与 checkpoint。
- 生成矩阵按局面而非 token 缓存，只能在同一次前向内复用，不能跨局面或模型版本保存。
- 实验不得改变围棋规则、合法动作语义、价值视角、MCTS 备份方向或 `fast`/`slow` 生命周期。

### 需要观察

- 动态分支范数、A/B 输出饱和比例、主干与超网络梯度范数及二者的更新比例。
- 启用前后的小数据过拟合速度、验证损失、编译图数量、显存、吞吐和非有限值发生率。
- 动态分支是否学到随局面变化的矩阵；如果输出接近常量，应与同参数量静态低秩分支比较。
- 只有在基线闭环通过验收后才启动本实验；结果无论成功或失败都写入开发日志。

## I-003：开源数据进入统一回放池

- **状态：** 待实现
- **动机：** 在自博弈变快之前先利用许可清晰的网络棋谱或富搜索数据预训练，但不建立第二套 Trainer 和样本语义。

### 初始玩法

未来的 SGF、KataGo 或其他网络数据先由各自适配器实现 `GameSource`，转换为统一 `GameRecord`，再通过 `ReplayStore.add_game()` 进入与自博弈相同的 SQLite 回放池。普通实战落子使用 `external/played_move` 来源和 one-hot 策略；有合法搜索访问数时使用 `search_visits` 语义。缺失的所有权或目差标签通过掩码关闭，不伪造零标签。

### 工程边界

- 外部解析器不得直接依赖或调用 Trainer；训练唯一数据入口仍是 `ReplayStore.sample_positions()`。
- 每个数据源必须先记录许可、具体版本、下载位置、文件校验值、规则解释和过滤统计。
- 本轮不实现下载、许可清单、SGF 解析、KataGo 格式适配或预训练命令。
