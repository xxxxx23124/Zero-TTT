# Zero-TTT 实验点子

这里是一块允许乱想、乱试、推翻和重写的区域。条目只表示“这个想法值得玩一下”，不表示它正确、有效、已经实现或必须进入主线。

## 使用规则

- 点子可以不做论文式消融，也不需要证明一定提升棋力。
- 每个实验必须能够被关闭，关闭后标准 AlphaZero 风格训练路径仍可运行。
- 真正运行时，把确切配置、checkpoint、结果和问题写入[开发日志](devlog/README.md)。
- 点子经过反复使用并形成长期约束后，才转写为[设计决策](design_decisions.md)。
- 失败、无聊或成本太高的点子可以标记为停止，不必删除历史。

## I-001：冻结—慢速—快速三个大脑

- **状态：** 待实验
- **动机：** 借鉴目标网络、指数移动平均和不同时间尺度参数的直觉，让快速学习获得一个较稳定的起点，同时保留不会随短期训练漂移的参考对象。

### 初始玩法

维护三份结构相同但生命周期不同的权重：

| 名称 | 初始职责 | 更新方式 |
| --- | --- | --- |
| `anchor` | 冻结的大脑，作为当前周期的参考或冠军 | 周期内不更新 |
| `slow` | 缓慢变化的大脑，吸收较长期的训练趋势 | 默认考虑从 `fast` 做 EMA 更新 |
| `fast` | 快速学习的大脑，负责正常优化 | 每个周期从 `slow` 初始化，再按训练梯度更新 |

一个最初版本的循环可以是：

1. 固定当前 `anchor`。
2. 用 `slow` 初始化新的 `fast`。
3. 使用当前数据训练 `fast`，同时让 `slow` 以较慢速度跟随。
4. 定期让 `fast` 或 `slow` 与 `anchor` 对局。
5. 如果按本次实验配置判断为“持续打不过”，允许用 `anchor` 重新初始化 `slow`，再开始下一周期。

### 必须保留的工程边界

- 三份权重在 checkpoint 中具有独立名称，加载时不能互相覆盖。
- 初始化、EMA 更新、评估和重置都产生可读日志。
- 训练策略只管理权重生命周期，不修改围棋规则、训练样本含义或 MCTS 价值视角。
- 关闭该实验时，只保留标准训练模型与冠军模型流程。

### 有意不固定的部分

- `slow` 是简单 EMA、分层 EMA、周期复制还是其他缓慢更新规则。
- EMA 系数、快速训练步数和一个周期包含多少盘棋。
- 比较 `fast`、`slow` 还是两者都与 `anchor` 对局。
- “持续打不过”的胜率阈值、对局数量和是否允许直接晋升新 `anchor`。
- 重置 `slow` 时是否同时清空优化器状态。

这些数值和分支在真正实现某次实验时写进配置；它们可以根据好玩程度随时修改。

## I-xxx：点子名称

它不能破坏哪些主线行为，怎样完整关闭。

### 实际记录
