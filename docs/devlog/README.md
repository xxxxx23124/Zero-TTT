# Zero-TTT 开发日志

本目录用于记录已经发生的开发与实验，不用于存放未来计划。

## 命名规则

每篇日志使用：

```text
YYYY-MM-DD-short-topic.md
```

同一天可以有多篇日志；`short-topic` 使用简短的小写英文和连字符，例如 `2026-08-20-mcts-smoke-test.md`。

## 日志模板

```markdown
# YYYY-MM-DD：主题

## 目标

本次准备验证或完成什么。

## 完成内容

实际修改、运行或检查了什么。

## 实验与结果

记录配置、可复现命令、指标、观察和失败结果。没有实验时写“无”。

## 产生的决策

列出新增或受影响的 `D-xxx`；没有时写“无”。

## 问题

当前已知缺陷、无法解释的结果和阻塞项。

## 下一步

下一次最小且可验证的行动。
```

## 维护规则

- 日志写事实，不把预期写成已完成结果。
- 失败实验和推翻的假设同样保留。
- 形成长期约束的选择必须同步到 `../design_decisions.md`。
- 日志引用实验产物时使用仓库相对路径，并注明生成该产物的配置或提交。
