# 2026-09-01：全链路严格 FP32

## 目标

删除训练和 publication 推理中的降精度分支，把模型张量、EMA、checkpoint、publication 和
evaluator 固定为严格 FP32，并确认 RTX 4090 Laptop 16 GB 仍可按阶段运行 625M 配置。

这次改造优先考虑方便和求稳。强化学习中的一部分有效梯度可能很小，在 16 位计算中可能下溢
为 0 或因舍入而无法形成有效更新；超网络的生成参数和反向链路也可能放大这种精度敏感性。
FP32 不保证收敛，但可以先排除混合精度及 loss scaling 带来的额外数值变量和排错成本。

## 完成内容

- 关闭 CUDA matmul/cuDNN TF32，删除 autocast 和 BF16 publication 转换；模型及推理契约拒绝
  非 FP32 浮点张量。
- 配置与模型产物升级到 schema v7，加入 `tensor_precision = "float32"`，正式 run 使用
  `rtx4090l-625m-fp32` 新身份。
- 正式 GPU smoke 改为训练、释放、推理三个生命周期边界，并修复缺失 `value_mask` 和旧
  `depth_mixing` 属性名。
- 根 README、架构、决策、路线图和源码旁文档统一声明长期严格 FP32 策略。

## 实验与结果

Docker 镜像为 PyTorch 2.13.0+cu132，设备为 RTX 4090 Laptop。所有测试均使用 batch 16、
activation checkpoint，smoke 累积设 1；正式配置仍为 256，累积不会提高单 microbatch 峰值。

| 配置/模式 | 训练 reserved | 推理 reserved | 稳态 microbatch | 推理首次执行 |
| --- | ---: | ---: | ---: | ---: |
| 默认 eager | 13.127 GiB | 3.979 GiB | 2.162 s | 0.546 s |
| baseline eager | 11.766 GiB | 3.053 GiB | 2.028 s | 0.539 s |
| 默认 compiled | 13.307 GiB | 4.295 GiB | 2.036 s | 40.470 s |

默认 compiled 训练预热含编译为 16.668 秒。三组均为 `matmul_precision=highest`、两项 TF32
关闭，参数、梯度和输出有限且保持 FP32。默认/基线参数量仍为 625,357,745/620,432,901。

改造前的临时探针还证明，GPU FP32 fast 与 GPU FP32 evaluator 同时常驻会达到
15.637 GiB reserved；这不符合生产按阶段运行的生命周期，也超过旧 14.5 GiB 线，因此不再
作为正式 smoke 结构。

复现命令：

```bash
docker compose run --rm dev python scripts/model_smoke_test.py \
  --configs configs/rtx4090l.toml --default-optimizer-steps 1 \
  --accumulation-steps 1 --disable-compile
docker compose run --rm dev python scripts/model_smoke_test.py \
  --configs configs/rtx4090l.toml --default-optimizer-steps 1 --accumulation-steps 1
```

## 产生的决策

D-040：全链路固定严格 FP32；未来其他精度必须重新决策并提升 schema。

## 问题

FP32 明显降低吞吐；该代价已接受，不通过隐式降精度规避。旧 v6 模型产物不能恢复。

## 下一步

在正式累积 256 和真实数据上执行长时稳定性测试，只评估吞吐、温度和阶段峰值，不改变精度。
